## A

### Abstain

To refrain from answering or acting.

**PT:** abster-se.

---

### Abstention

Choosing not to answer when the system lacks sufficient evidence.

---

### Accountability

Responsibility for the outcomes of a decision or action.

Accountability stays with people and organizations; it cannot be delegated to a model.

**PT:** responsabilização / prestação de contas.

---

### Accountability Vacuum

A situation where responsibility becomes unclear or is shifted away from humans.

Typical sign: "the agent decided" is given as the explanation for an outcome, and no person owns it.

---

### Adapter

A small set of additional parameters used to modify or specialize the behavior of a base model without retraining the whole model.

Common example: **LoRA adapter**.

```text
Base Model + Adapter → Specialized Model
```

---

### Adversarial Perturbation

A carefully crafted small modification to an input designed to cause unexpected or harmful model behavior.

---

### Agent Autonomy

The degree to which an agent can act without constant human approval.

Autonomy should grow with the reliability of the agent and shrink with the stakes and irreversibility of the action.

**Think:** how long the leash is.

---

### Agent Harness

The system around a model that manages tools, context, state, permissions, execution, and controls.

```text
Agent = Model + Harness
```

Most governance controls live in the harness, not in the model.

---

### Agent Identity

A verifiable identity assigned to an agent when it interacts with other systems.

Allows permissions, audit trails and accountability to be tied to a specific agent.

---

### Agent Registry

A governed inventory of deployed agents and their metadata.

It may include:

- owner
- purpose
- permissions
- tools
- model version
- status

---

### Agent Runtime

The execution environment where an agent runs in production.

---

### AIBOM — AI Bill of Materials

An inventory of the AI-related components used in a system.

It may include:

- models
- datasets
- adapters
- tokenizers
- frameworks
- inference runtimes
- external AI services

Useful for provenance, security, governance and compliance.

**Think:** AI ingredients list.

---

### Approval Gate

A checkpoint that requires approval before an action can continue.

Commonly used before irreversible or high-stakes actions such as payments, deletions or external communication.

---

### Artifact

A file or output produced or consumed during the development and deployment process.

Examples:

- model weights
- checkpoints
- LoRA adapters
- `.safetensors`
- GGUF files
- ONNX models
- containers

---

### Assumption

An idea or condition treated as true without having been directly verified.

In AI systems, assumptions should be clearly distinguished from verified facts.

**PT:** suposição.

---

### Attestation

A mechanism used to verify that a device, environment or software instance is running in an expected and trusted state.

Often used in device and infrastructure security.

---

### Audit Trail

A record of actions and events used to understand what happened and who acted.

---

### Authorization

The process of determining whether an authenticated user, agent, or service is allowed to perform a specific action or access a resource.

Authentication answers **who are you?**

Authorization answers **what are you allowed to do?**

---

## B

### Backdoor

Hidden malicious behavior intentionally inserted into a model or system.

It may remain inactive until a specific trigger is provided.

```text
Normal input → Normal behavior
Trigger → Malicious behavior
```

---

### Baseline

A reference representing normal system behavior or resource usage, used to identify unusual deviations.

---

### Biased Output

An output influenced by distorted, unfair or systematically skewed patterns in the model, training data or other system components.

**PT:** saída enviesada / tendenciosa.

---

### Blast Radius

The maximum scope of damage or impact that a compromised component, account or system can cause.

---

## C

### Capability

A function or resource a system exposes for another component to use.

Exposing a capability does not mean every caller is authorized to use it.

---

### Capability Boundary

A defined interface separating what capabilities a service exposes from how they are internally implemented.

---

### Chain-of-Thought Prompting

Prompting a model to reason through intermediate steps before producing an answer.

Often improves results on multi-step problems such as math, logic and planning.

---

### Chat Template

A formatting template that converts structured chat messages and roles into the token sequence expected by a specific model.

---

### Circuit Breaker

A control that automatically stops execution when predefined limits such as cost, time, steps or recursion depth are reached.

---

### Claim

A factual statement that can be checked against evidence.

**PT:** afirmação.

---

### Claim-Check-Act

A safety pattern that separates model generation from execution.

```text
Claim
  ↓
Check
  ↓
Act
```

The model may propose or infer something, but the claim must be independently verified before an action is executed.

---

### Claim-Level Evaluation

Evaluating individual factual claims instead of judging the entire answer as one unit.

```text
Answer → split into claims → check each claim against evidence
```

---

### Classifier

A model or system that assigns inputs to predefined categories.

---

### Cold Start

The delay caused by starting a new compute instance before it can process a request.

---

### Concurrency

The number of operations or tasks that are running at the same time.

---

### Confidence Score

A value representing how confident a classifier is in its prediction.

Often compared against a threshold to decide whether to accept the result or escalate.

---

### Constraint

A restriction that limits what is possible or allowed.

**PT:** restrição.

---

### Constraint Prompting

Explicitly defining rules, limitations, or conditions the model must follow.

A constraint in the prompt guides behavior but does not enforce it; see Technical Control.

---

### Content Security Policy — CSP

A browser security mechanism that restricts which resources, scripts, frames, and other content a web page is allowed to load or execute.

Useful as defense in depth against attacks such as XSS.

---

### Context Injection

Adding relevant external information to the prompt so the model can use it when generating a response.

RAG is a common form of context injection.

Not to be confused with prompt injection, which is an attack.

---

### Context Window

The maximum amount of information or tokens a model can process within one inference context.

---

### Context-Aware Output Encoding

Encoding model output according to the environment where it will be used.

Examples:

- HTML → HTML encoding
- JavaScript → JavaScript encoding
- URL → URL encoding
- database values → parameterized queries

There is no universal escaping strategy for every output context.

---

### Continuous Learning

A process where a model or system keeps learning from newly collected data after its initial deployment.

---

### Control Character

A non-printable character that controls how a terminal, log viewer, protocol, or other system behaves rather than representing visible text.

Examples include:

- ANSI escape sequences
- BEL
- carriage return
- backspace
- OSC sequences

---

### Corpus / Corpora

A collection of text or data used for training, evaluation or analysis. **Corpora** is the plural of corpus.

---

### Correct Abstention

Correctly refusing to answer when sufficient evidence is unavailable.

In evals, a correct abstention counts as a success, not as a failure.

---

### Correlated Errors

Errors that tend to occur together because evaluators or models share similar behavior or biases.

Example: a judge model from the same family as the evaluated model may miss the same mistakes.

---

### Cosine Similarity

A metric commonly used to measure how similar two embedding vectors are based on the angle between them.

Higher similarity generally means that two vectors are considered more semantically related.

Commonly used in vector search and RAG.

---

### Cost Asymmetry

A situation where a small or inexpensive attacker action causes a disproportionately large computational or financial cost for the target system.

---

### Cross-Tenant Leakage

Exposure or inference of information belonging to one tenant by another tenant in a multi-tenant system.

In vector systems, this may happen when similarity search runs across a shared index before tenant-level filtering is applied.

---

### Curated Dataset

A dataset that has been intentionally selected, reviewed, cleaned and organized for a specific purpose or domain.

---

## D

### Data Exfiltration

Unauthorized transfer of sensitive or protected data from an internal system to an external destination.

---

### Data Poisoning

Manipulation or contamination of data so that a model learns incorrect, biased or malicious behavior. It can be intentional or accidental.

---

### Decision Model

A model designed primarily to make structured decisions rather than generate free-form text.

---

### Decoupling

Reducing dependency between system components so they can evolve or scale independently.

---

### Deduplication

The process of detecting and removing duplicate or near-duplicate data.

Semantic deduplication may use embedding similarity rather than exact text matching.

---

### Delegated Execution

Execution performed independently by an agent within limits defined by humans.

```text
Human defines scope + limits → Agent executes inside them
```

---

### Denial of Wallet — DoW

An attack that deliberately causes excessive paid resource usage until operating the service becomes financially unsustainable.

---

### Deploy / Deployment

To put a system into an environment where it runs and is used; the deployment is the result of that process.

**PT:** implantar / implantação.

---

### Deprecated

A component that is still available but is no longer recommended or actively maintained.

Deprecated components may stop receiving security fixes.

---

### Deterministic Eval

An evaluation based on explicit rules with predictable results.

Examples: exact match, regex, schema validation, checking whether a tool was called.

---

### Developer Instructions

Internal instructions provided by the application developer to guide model behavior.

They are normally not intended to be visible to the end user, but should still be treated as potentially discoverable.

---

### Digest

A cryptographic identifier derived from the exact content of an artifact.

Frequently used to reference immutable versions of artifacts.

Example:

```text
sha256:...
```

---

### Distillation

A technique where one model is trained using outputs from another model as supervision. It can also be abused to create an unauthorized functional approximation of a proprietary model.

---

### Downstream

Refers to models, systems or processes that depend on the output of an earlier component in a pipeline.

---

### Downstream Operation

An action triggered later in a workflow as a consequence of an earlier request or tool call.

---

### Drift

A gradual change in data distribution or model behavior over time. Drift may indicate degradation, environmental changes or unexpected system behavior.

---

### Durable Corruption

A persistent change to data, memory or model behavior that continues affecting the system beyond a single inference or session.

---

### DVC — Data Version Control

A version-control system for datasets, models and ML artifacts. It helps track changes, reproduce previous versions and roll back when necessary.

---

## E

### Embedding

A numerical vector representation of data such as text, images or audio, designed to capture semantic relationships.

---

### Embedding Inversion

An attack that attempts to reconstruct original or approximate source content from its embedding vectors.

```text
Embedding
   ↓
Inversion
   ↓
Approximate Source Data
```

**Important:** Embedding ≠ anonymous data.

---

### Enforce

To make a rule actually be followed, usually through a mechanism rather than a request.

**PT:** fazer cumprir / impor.

---

### EOS — End-of-Sequence Token

A special token used to indicate that model generation should stop.

---

### Escalation

Forwarding a case to a higher level of decision, such as a stronger evaluator or a human.

**PT:** escalonamento.

---

### Escaping

Transforming special characters so they are interpreted as data rather than executable syntax or control instructions.

The correct escaping method depends on the destination context.

---

### Eval Suite

A collection of evaluation cases used to test a system repeatedly, for example after every model, prompt or tool change.

---

### Evaluation / Eval

A test used to measure whether an AI system behaves according to defined criteria.

---

### Evaluation Cascade

A sequence where simpler evaluators handle easy cases and harder cases escalate to stronger evaluators.

```text
Deterministic check → Classifier → LLM judge → Human review
```

---

### Evidence

Information that supports or refutes a claim.

**PT:** evidência.

---

### Execution Trace

The recorded sequence of model calls, tool calls, states, and outputs from one agent run.

Useful for debugging, evaluation and audit.

---

## F

### Fan-Out

A pattern where one action triggers multiple additional actions, which may themselves trigger more actions.

---

### Feedback Loop

A process where system outputs or user feedback are fed back into future decisions, training or model updates. Poorly controlled feedback loops can amplify errors or poisoning.

---

### Few-Shot Prompting

Providing a small number of examples to guide the model toward the desired behavior or output format.

```text
Example 1 → Example 2 → Example 3 → New input
```

---

### Fine-Tuning

Additional training performed on an existing model to adapt it to a specific task, domain or behavior.

---

### Forged Evidence

Fabricated or manipulated information presented as if it were legitimate evidence.

Examples:

- nonexistent reports
- fabricated citations
- fake tool results
- invented records

---

### Function Schema

A structured description of a function available to an LLM or agent.

It may define:

- function name
- parameters
- parameter types
- descriptions
- required fields

Function schemas can reveal application capabilities and should not be treated as secrets or authorization mechanisms.

---

## G

### Govern / Governed

**Govern** means to control through rules and mechanisms. **Governed** means subject to governance mechanisms.

**PT:** governar / governado.

---

### Governance by Design

Embedding governance controls directly into the system architecture instead of relying only on policies, documents or model instructions.

---

### Graceful Degradation

A design strategy where the system reduces functionality under stress instead of completely failing.

---

### Grounded Answer

An answer whose claims are supported by an approved source or retrieved context.

A grounded answer is not necessarily factually correct: the source itself may be wrong.

---

### Groundedness

The degree to which a model's claims are supported by the provided or authoritative evidence.

A response can be fluent and confident while having poor groundedness.

---

### Grounding

Connecting model outputs to external or verifiable information instead of relying only on the model's internal knowledge.

---

### Guardrail

A technical or procedural control designed to constrain an AI system's behavior and reduce unsafe or undesired actions.

Examples:

- input and output filters
- tool-risk gating
- approval gates
- hard stops

Guardrails enforced by the system are stronger than instructions written only in the prompt.

---

## H

### Hard Spending Cap

A strict budget limit that stops further execution or API usage when the configured financial threshold is reached.

---

### Hard Stop

A technical control that blocks execution when a predefined condition is met.

Unlike a prompt instruction, a hard stop is enforced by the system and cannot be talked around by the model.

---

### Hardening

The process of reducing a system's attack surface and strengthening its security configuration.

---

### Hash

A fixed-length value generated from data.

It can be used to detect whether an artifact has changed.

```text
Expected hash == Actual hash
→ artifact unchanged
```

A different file produces a different hash.

---

### Hash Pinning

Referencing or validating an artifact using its expected cryptographic hash.

This helps prevent silently replacing one artifact with another.

---

### Hidden Context

Information available to the model but not normally displayed to the end user.

It may include:

- system prompts
- developer instructions
- RAG policies
- tool schemas
- workflow rules
- profile context

**Hidden ≠ secret.**

---

### High-Stakes Decision

A decision whose consequences may significantly affect people, money, rights, safety, or operations.

High-stakes decisions usually require stronger controls, such as approval gates and human review.

---

### Horizontal Scaling

Increasing capacity by adding more instances rather than making one instance larger.

Much easier when the service is stateless.

---

### Human Label

A reference evaluation or classification created by a human.

Used as ground truth to measure how well automatic evaluators agree with people.

---

### Human Oversight

Human supervision over AI decisions and actions.

It can happen before (approval), during (monitoring) or after (review and audit) an action.

---

## I

### Immutable Reference

A reference that always identifies the exact same artifact.

Example:

```text
sha256:abc123...
```

Unlike mutable references such as:

```text
latest
```

---

### Improper Output Handling

Unsafe use of LLM-generated output before it is passed to another component or system.

```text
LLM → shell
LLM → SQL
LLM → browser
LLM → filesystem
LLM → tool
```

Model output should be treated as untrusted input.

---

### Incorrect State Inference

A failure where a model assumes that a system condition is true without verifying the real state.

Example:

```text
LLM: payment = confirmed

Actual system:
payment = pending
```

Inferred state ≠ verified state.

---

### Inference

The stage where a trained model receives an input and generates a prediction or output.

```text
Input → Model → Output
```

---

### Inference Endpoint

A network endpoint or API through which applications send inputs to a deployed model and receive inference results.

---

### Input Schema

A structured definition of the arguments accepted by a tool.

See also: Tool Schema.

---

### Integrity

The assurance that data or an artifact has not been changed or tampered with unexpectedly.

In supply-chain security:

> Is this still the exact artifact I expected?

---

### Intent Classification

Identifying the purpose or intent behind a user request.

---

### Interchangeable Workers

Workers capable of handling any request independently because no local session state is required.

---

## J

### Jev

A decision/classification model designed for fast, structured semantic judgments.

---

### Judge Model

The model responsible for evaluating another system's output or behavior.

---

## L

### Label Poisoning

A type of data poisoning where examples are intentionally or accidentally assigned incorrect labels so the model learns wrong patterns.

---

### Leakage

Unintended exposure or passing of information to where it should not be.

**PT:** vazamento.

---

### Least Privilege

Giving a user, agent, or service only the minimum permissions required to perform its task.

Reduces the blast radius if the component is compromised or misbehaves.

---

### Lineage

The history of how data or an artifact moved and changed through a pipeline, including transformations, versions and dependencies.

---

### LLM-as-a-Judge

Using an LLM to evaluate another model's or agent's output.

Flexible, but the judge can share the same biases and blind spots as the system being evaluated.

---

### Load Balancing

Distributing incoming requests across multiple service instances.

---

### Log-Probabilities

The logarithms of token probabilities produced by a model. They provide more detailed information about how likely different outputs are.

---

### Logits

Raw numerical scores produced by a model before they are converted into probabilities.

---

### Long-Running Operation

A task that continues execution over an extended period rather than within a short request window.

Usually requires persisted state, progress tracking and the ability to resume.

---

### LoRA — Low-Rank Adaptation

A PEFT technique that adds small trainable matrices to a frozen base model.

Instead of retraining all model parameters, LoRA trains a much smaller number of parameters.

```text
Base Model
   +
LoRA
   ↓
Adapted Model
```

## M

### MCP — Model Context Protocol

A standardized protocol for connecting AI applications to tools, resources, and external systems.

```text
MCP Host → MCP Client → MCP Server → REST / API / service
```

---

### MCP Client

The component inside the host that communicates with an MCP server.

Usually one client per server connection.

---

### MCP Host

The application that runs or coordinates the AI model and connects to MCP servers.

---

### MCP SDK Primitives

Common building blocks of the MCP Python SDK:

- `list_tools()` — retrieves the tools available from a server (tool discovery)
- `call_tool()` — invokes a tool exposed by a server
- `@mcp.tool()` — decorator that exposes a Python function as an MCP tool
- `TextContent` — content representation for textual responses
- `is_error` — field indicating whether a tool result represents an error

---

### MCP Server

A service that exposes tools, resources, or capabilities through MCP.

---

### Membership Inference

An attack that tries to determine whether a specific piece of data exists in a dataset or index without necessarily retrieving its contents.

In vector systems, similarity scores, timing, or response patterns may reveal membership.

---

### Misattributed Evidence

Real or fabricated information incorrectly attributed to the wrong source, document, person, or authority.

---

### Misinformation

Incorrect, incomplete, unsupported, or misleading information produced by an AI system that may influence a human decision or automated action.

The primary risk is not only generating incorrect information, but having that information trusted and acted upon.

---

### Mixed Leakage

An answer that is mostly grounded but includes unsupported information.

Hard to detect when the answer is judged as a single unit; claim-level evaluation helps catch it.

---

### Model Card

Documentation describing a model.

It may contain:

- intended use
- limitations
- training information
- evaluation results
- licensing information

However:

> **Model Card ≠ proof of origin**

---

### Model Extraction

Repeatedly querying a model to collect enough information to approximate, reproduce or imitate its behavior.

---

### Model Poisoning

Manipulation of a model or its learning process to introduce harmful, biased or attacker-controlled behavior.

---

### Model Provenance

The traceable history and origin of a model.

It may describe:

- who created it
- the base model
- datasets used
- fine-tuning
- transformations
- versions
- ownership

---

### Multimodal

A system capable of processing more than one type of data, such as text, images, audio or video.

---

### Mutable Reference

A reference whose target may change over time.

Example:

```text
model:latest
```

Today it may point to one artifact and later point to another.

---

## N

### Narrow Decision

A small, clearly defined decision with a limited set of possible outputs.

---

## O

### Omission Failure

A failure caused by leaving out information that is necessary for a correct decision.

Examples:

- missing exceptions
- missing risks
- missing deadlines
- missing conditions
- missing timestamps

The remaining information may appear correct while still being misleading.

---

### Operational Autonomy

The ability to independently execute actions and workflows.

Having operational autonomy does not transfer accountability away from the humans or organization that deployed the agent.

---

### Outcome

The result or consequence of a decision or action.

**PT:** resultado / consequência.

---

### Output Budget

The maximum amount of output a model is allowed to generate for a request.

---

### Output Encoding

Transforming output so special characters are interpreted safely as data instead of executable code or markup.

Example:

```text
<script>
```

may be encoded for HTML so the browser displays it as text rather than executing it.

---

### Output Formatting

Specifying the exact structure or format expected from the model, such as JSON, XML, or a schema.

See also: Typed Output.

---

### Overfitting

When a model learns the training data too specifically, including noise, exceptions, or accidental patterns, instead of learning patterns that generalize well.

As a result, it performs very well on the data it has seen, but worse on new or unseen data.

**Think:** memorizing the answers instead of learning the subject.

---

### Overreliance

Excessive trust in AI-generated output.

It often occurs because fluent, confident, or well-structured responses appear authoritative.

**Fluency ≠ correctness. Confidence ≠ evidence.**

---

### Oversight

Supervision or monitoring of an activity.

**PT:** supervisão.

---

### Ownership

Responsibility assigned over something, such as a system, agent or decision.

**PT:** responsabilidade / posse (de quem é o dono).

---

## P

### Parameterized Query

A database query where data values are supplied separately from the SQL command structure.

Instead of constructing SQL using model-generated strings:

```text
SQL + arbitrary value
```

the SQL structure remains fixed and values are treated as data. This reduces SQL injection risk.

---

### Path Traversal

A vulnerability where an attacker manipulates a file path to access files outside the intended directory.

Common pattern:

```text
../../
```

LLM-generated file paths must be validated before filesystem access.

---

### PEFT — Parameter-Efficient Fine-Tuning

Fine-tuning techniques that update only a small portion of model parameters instead of retraining the entire model.

Benefits include:

- less memory
- lower compute cost
- faster training
- smaller artifacts

LoRA is one example of PEFT.

---

### Poisoning

The intentional manipulation of training data, models or other AI components to influence future model behavior.

Examples:

- training data poisoning
- model poisoning
- embedding poisoning

---

### Pre-Flight Token Estimation

Estimating token usage and expected cost before sending a request to the model, allowing overly expensive requests to be rejected early.

---

### Prepared Statement

A predefined database query structure where parameters are supplied separately from SQL syntax.

Prepared statements help prevent untrusted data from becoming executable SQL.

---

### Privilege Separation

A security principle that separates tasks and components according to the privileges they require.

A component should not automatically inherit access to capabilities that are unnecessary for its task.

---

### Probing

Repeatedly interacting with a system to discover:

- hidden behavior
- internal rules
- limits
- permissions
- available tools
- potential weaknesses

---

### Prompt Chaining

Breaking a complex task into multiple sequential prompts, where each step feeds the next.

```text
Prompt 1 → Output 1 → Prompt 2 → Output 2 → Final result
```

---

### Prompt Decomposition

Splitting a complex problem into smaller, simpler subproblems before solving it.

Often combined with prompt chaining: decomposition defines the steps, chaining runs them in sequence.

---

### Prompt Template

A reusable prompt structure with placeholders for dynamic inputs.

Example: `Summarize the following document for {audience}: {document}`.

---

### Protocol Boundary

The point where one communication protocol ends and another begins.

Example: an MCP server receives MCP requests and translates them into REST calls to a backend service.

---

### Provenance

The origin and history of an artifact.

It answers questions such as:

- Where did it come from?
- Who created it?
- What transformations were applied?
- Was it modified?
- Which version is this?

**PT:** proveniência / rastreabilidade de origem.

---

## Q

### Quantization

A technique that reduces the numerical precision of model weights to reduce memory usage and computational cost.

Example:

```text
FP16 → INT8 → INT4
```

The quantized model is a new artifact and should be evaluated independently.

---

### Queue

A collection of actions or tasks waiting to be executed.

---

### Quota

A predefined limit on resource consumption, such as requests, tokens, compute, storage or cost.

---

## R

### RAG — Retrieval-Augmented Generation

An architecture where external information is retrieved and provided to the model as context before it generates an answer.

---

### RAG Poisoning

Manipulation of a RAG knowledge base so malicious or misleading content is retrieved and influences model outputs.

---

### Rate Limiting

Restricting how frequently a user, application or source can perform actions or send requests within a defined period.

---

### RCE — Remote Code Execution

A vulnerability that allows an attacker to cause arbitrary code or commands to execute on another system.

In LLM applications this may happen when model output is passed directly to:

- shell commands
- `exec`
- `eval`
- unsafe interpreters

---

### Reasoning Loop

A situation where a reasoning model repeatedly processes the same or related steps without reaching a useful termination state.

---

### Recursion Depth

The number of nested recursive calls or agent/sub-agent levels currently active.

---

### Red Teaming

Adversarial testing of a system to identify vulnerabilities, unsafe behaviors and possible attack paths before real attackers exploit them.

---

### Reliability

The ability of a system to consistently behave as expected over time.

**PT:** confiabilidade.

---

### Resource Allocation

The process of assigning and limiting compute, memory, tokens or other resources among users, requests or workloads.

---

### Resource Exhaustion

A condition where resources such as GPU, CPU, memory, tokens, connections or API quota are consumed until service performance degrades or fails.

---

### REST API

An HTTP-based interface commonly used by services to expose operations and resources.

---

### Retrieval Jamming

An availability attack against a retrieval system where specially crafted content interferes with useful retrieval.

```text
Query
  ↓
Blocker Document
  ↓
Bad Retrieval
  ↓
Refusal / Missing Answer
```

Unlike prompt injection, the retrieved content does not necessarily contain malicious instructions.

---

### Reverse Engineering

The process of studying a system's behavior, structure, or outputs to infer how its internal mechanisms work.

In AI security, this may be used to infer:

- refusal rules
- hidden instructions
- thresholds
- tools
- workflows

---

### Reversibility

How easily an action or decision can be undone.

```text
Reversible + low stakes    → more autonomy
Irreversible + high stakes → approval gate / hard stop
```

---

### Risk Classification

Assigning an action or input to a predefined risk level.

---

### RLHF — Reinforcement Learning from Human Feedback

A training technique that uses human preferences or feedback as a signal to shape model behavior.

---

### Role Prompting

Assigning the model a specific role, perspective, or expertise to shape its behavior.

Example: "You are a security reviewer…".

---

### Runtime

The environment or moment in which a program is executing.

**PT:** tempo / ambiente de execução.

---

### Runtime Verification

Checking conditions and system state at the moment an action is about to execute.

Used especially for high-impact actions.

```text
LLM proposes action
        ↓
Runtime Check
        ↓
Allow / Reject
```

## S

### Sandbox / Sandboxing

An isolated environment that restricts what a model, agent or untrusted component can access or execute.

---

### Sanitization

Removing, modifying, or neutralizing potentially dangerous content before it reaches another component.

Examples include removing:

- dangerous HTML
- control characters
- unsafe URLs
- unexpected markup

Validation asks whether something is allowed. Sanitization makes dangerous content safer.

---

### SBOM — Software Bill of Materials

An inventory of software components and dependencies used by an application.

It may contain:

- package names
- versions
- dependencies
- licenses
- vulnerability information

**Think:** software ingredients list.

---

### Scope / Scoped

**Scope** is the boundary of what something covers or is allowed to do. **Scoped** means limited to a specific scope.

**PT:** escopo / limitado a um escopo.

---

### Scoped Permission

A permission restricted to a specific resource or action.

Example: `read` access to one folder instead of `read/write` access to the whole drive.

---

### Security Boundary

A boundary where security controls determine whether access or an action is allowed.

System prompts and hidden instructions should not be treated as security boundaries.

---

### Self-Consistency

Generating multiple reasoning paths and selecting the most consistent answer across them.

```text
Same question → N reasoning paths → majority / most consistent answer
```

---

### Semantic Cache

A cache that uses semantic similarity rather than exact matching to reuse previous results.

```text
New Query
   ↓
Embedding Similarity
   ↓
Similar Cached Query?
   ↓
Reuse Response
```

Its similarity threshold can become an attack surface.

---

### Semantic Classifier

A classifier that makes decisions based on meaning rather than exact rules.

---

### Semantic Evaluation

Evaluation based on meaning rather than exact string or rule matching.

---

### Serialization

The process of converting an object or model into a format that can be stored or transferred.

Some serialization formats may execute code while loading.

Example:

```text
Python pickle
```

---

### Session State

Information stored and reused throughout a session.

---

### Session-Oriented Architecture

An architecture where interactions depend on a persistent session.

---

### Similarity Score

A numerical measurement representing how similar two vectors are.

Similarity scores are commonly used to rank retrieval results.

Exposing raw scores may enable information leakage or membership inference.

---

### Sleeper Agent

A model containing hidden behavior that stays dormant until a specific trigger or condition activates it.

---

### Slopsquatting

A supply-chain attack where an AI coding assistant suggests a plausible but nonexistent package name and an attacker registers that package with malicious code.

```text
LLM invents package
        ↓
Attacker registers it
        ↓
Developer installs it
```

### Sociotechnical System

A system formed by technology, people, organizations, processes, and context.

An AI system's risks and outcomes depend on all of these parts, not only on the model.

---

### Special Token

A token with structural or control meaning to a model, such as tokens representing system, user, assistant or end-of-sequence boundaries.

---

### Sponge Example

An adversarial input intentionally optimized to cause unusually high computational resource consumption.

The level of consequence or importance involved in a decision or action.

**PT:** o que está em jogo / nível de consequência.

### State Hashing

Generating hashes from agent states so repeated states can be detected, helping identify loops or repeated execution patterns.

---

---

---

---

A transport that communicates through standard input and output streams.

---

### Streamable HTTP

An MCP transport that communicates over HTTP and supports streamed communication.

## Key Distinctions

### Signed ≠ Safe

A valid digital signature can prove:

- origin
- integrity

It does **not** prove that the model behaves safely.

---

### Safe Format ≠ Safe Model

A secure serialization format reduces some technical risks but does not guarantee that the model itself has no:

- backdoors
- bias
- poisoned behavior

---

### Provenance vs Integrity

**Provenance**

> Where did this artifact come from?

**Integrity**

> Has this artifact changed since it was created or approved?

---

### Supply Chain vs Poisoning

**Poisoning** focuses on malicious manipulation of the model or data.

**Supply Chain** focuses on how a compromised component entered or propagated through the system.

The same incident may involve both.

---

### Operational Autonomy ≠ Accountability

An agent can execute actions on its own, but responsibility for the outcome stays with the people and organization that deployed it.

---

### Agent Autonomy ≠ Unrestricted Permissions

Autonomy is about acting without constant approval. Permissions should still follow least privilege and scoped access.

---

### Capability ≠ Authorization

A server exposing a capability only says **what can be done**. Authorization decides **who is allowed to do it**.

---

### Tool Schema ≠ Permission

A tool schema describes how to call a tool. It does not grant or check permission to call it.

---

### Stateful Agent ≠ Stateful MCP Server

An agent can keep conversation and task state in its harness while the MCP servers it calls stay stateless and horizontally scalable.

---

### Agent ≠ Harness

The **agent** is the behavior that emerges from model + harness. The **harness** is the surrounding system that manages tools, context, state, permissions and controls.

---

### MCP ≠ REST

MCP is a protocol between AI applications and tool servers. REST is a common interface between services. They often appear together:

```text
MCP Client → MCP Server → REST / API / service
```

---

### Grounded Answer ≠ Factually Correct Answer

Grounded means **supported by the provided source**. If the source is wrong or outdated, a grounded answer can still be incorrect.

---

### Deterministic Check ≠ Semantic Evaluation

A **deterministic check** follows explicit rules (exact match, regex, schema). A **semantic evaluation** judges meaning, which requires a classifier, an LLM or a human.

---

### Classifier ≠ LLM-as-a-Judge

A **classifier** returns a constrained category, often with a confidence score. **LLM-as-a-judge** uses a general model to evaluate with free-form reasoning. Classifiers are faster and more predictable; LLM judges are more flexible.
